# 스윙 룰 스킬 모의투자 계획 (사전 등록)

## 목적

"내 스윙 룰" 스킬(엔진 `trading/swing_engine`)을 실전에 써도 되는지, 돈을 넣기 전에 판정한다. 판정 기준은 **모의투자를 시작하기 전에** 이 문서에 고정한다. 기간 중에는 기준을 바꾸지 않는다.

## 이 모의투자가 검증하는 것과 못 하는 것

| 검증한다 | 검증하지 못한다 |
|---|---|
| 룰이 정확히 실행되는가 (신호·진입·손절·청산·수량) | 이 룰이 장기적으로 돈을 버는가 |
| 신호를 사후에 고치지 않았는가 (커밋 시각 증거) | 3개월 표본으로 우위가 있다는 통계적 증명 |
| 매일 빠짐없이 돌아가는가 | 실제 체결 품질 (호가·슬리피지) |
| 성과가 백테스트에서 기대한 범위 안에 있는가 | 생존편향 없는 성과 |

- 룰의 수익성 근거는 **10년 백테스트**(`swing-results` 브랜치)와 **대표님 스캐너 자체의 백테스트·실전 검증**(2026-07-17 시작)이 맡는다.
- 10년 백테스트는 현재 구성종목 기준이라 생존편향이 있다. 그날의 실제 구성종목으로 다시 계산한 결과(`docs/swing-backtest-robustness-2026-09-26.xlsx`)를 함께 본다. 시장별 실전 투입 범위는 아래 "실전 투입 결정"에 따른다.
- 승률 30%대, 소수의 큰 승자에서 수익이 나는 구조라서 몇 달 성과는 운에 크게 좌우된다.

## 운영 방식

| 항목 | 내용 |
|---|---|
| 시장 | S&P500, 나스닥100, 코스피, 코스닥, 크립토 (시장별 별도 장부, 각 1억 원 상당으로 시작) |
| 실행 | `swing-paper-keeper` 워크플로우가 2시간마다 5개 시장 실행을 수동 실행 방식으로 요청한다(GitHub 예약 실행은 보조). 주식은 마감 후 90분이 지난 봉만 쓴다(Yahoo가 마감 뒤에도 거래량을 고치고 진입 조건이 거래량을 봄). 데이터가 준비된 첫 실행이 신호를 커밋하고, 이미 커밋된 날이나 장중인 시장은 아무것도 커밋하지 않음 |
| 신호 선기록 | 그날 신호를 `paper-trading` 브랜치에 **먼저 커밋**한 뒤 장부를 갱신한다. 주식은 커밋 시각이 다음 시가보다 앞서야 한다. 크립토는 신호 봉 마감(00:00 UTC)과 시가가 같은 시각이고 Yahoo가 마감한 날의 봉을 몇 시간 늦게 올려서, 다음 봉이 마감하기 전(마감 후 24시간 안)에 커밋해야 한다 |
| 시작일 | 제시간에 실행된 첫날의 마감으로 확정한다. 휴장일 뒤처럼 늦은 첫 실행은 시작일을 만들지 않고 다음 실행을 기다린다 |
| 유니버스 | 시작일에 받은 구성종목 목록을 기간 내내 고정한다 (`config.json`) |
| 체결 가정 | 다음 시가 진입, 손절은 `min(시가, 손절가)`, 50일선 종가 이탈 시 다음 시가 청산, 편도 비용 0.2% |
| 수량 | 자본 × 0.75% ÷ 손절폭. 현금 한도 안에서 RS 높은 순서로 배분 |
| RS | 유니버스 백분위 70 이상 (스캐너 룰) |
| 데이터 확인 | 지수의 마지막 봉을 가진 종목이 90% 미만이거나, 크립토의 전날 봉이 아직 없거나, 받은 데이터의 마지막 봉이 장부에 이미 있는 날(최신 신호 파일·시작일)보다 이전이면 아무것도 커밋하지 않는다. 다음 2시간 주기 실행이 다시 시도한다 (수동 실행은 주식만 10분 간격으로 3번 다시 받음) |
| 재계산 대조 | 매일 장부를 시작일부터 다시 계산해서 이미 커밋한 신호와 비교한다. 어긋나면 원인(데이터 수정 등)을 기록한다 |

## 판정 기준 (고정)

**기간:** 가동일부터 **최소 60거래일**. 20거래일에 중간 점검을 한다.

| # | 항목 | 통과 기준 |
|---|---|---|
| A | 무결성 | 모든 신호 파일의 커밋 시각이 해당 시장의 다음 시가보다 앞섬: 위반 0건. 재계산 신호와 커밋 신호의 설명되지 않는 불일치: 0건 |
| B | 운영 | 시장별 실행 누락 2회 이하 (누락해도 다음 실행이 복구). 데이터를 못 받은 종목 5% 이하 |
| C | 룰 준수 | 목표가 매도 0건. 갭을 제외하고 손절폭을 넘는 손실 0건. 손절·50일선 외 청산 0건 |
| D | 건전성 | 모의 성과가 **같은 길이 백테스트 구간들의 하위 5%** 밑이면 경고. 평균 손실이 백테스트 평균 손실 ±3%p를 벗어나면 경고. 기준값은 아래 표 |
| E | 스캐너 대조 (선택) | 대표님 맥 스캐너 타점표를 받을 수 있으면 신호 일치율 90% 이상. 불일치는 추정값 7개 차이로 원인을 분석한다 |

**판정:**
- **A·B·C 통과, D 경고 없음** → 실전 소액 적용 가능. 계획 비중의 1/4로 시작하고, 20거래일마다 다시 점검한다.
- **A 또는 C 실패** → 원인을 고친 뒤 새 기간으로 다시 시작한다. 이전 기록은 보존한다.
- **D 경고** → 대표님이 검토한다. 룰 문제인지 시장 국면 문제인지 구분한다.

**기간 중 금지:** 룰·파라미터 변경. 바꿔야 하면 기간을 끝내고 새 기간으로 다시 시작한다.

## 알려진 한계

- **추정값 7개:** 피벗 기간, 거래량 평균 기간, RS 계산 방식, 52주 고저 기준, 200일선 상승 기간, 수축비, 비용이 맥 스캐너 원본과 다를 수 있다 (`trading/SPEC.md` 9절).
- **유니버스 근사:** 현재 지수 구성종목 기준이라 생존편향이 있다. 코스피·코스닥은 시가총액 상위 200·150개로 지수 구성종목을 근사한다.
- **Yahoo 한국장 데이터의 저녁 공백:** Yahoo가 그날의 코스피·코스닥 봉을 마감 뒤 몇 시간 동안 주다가 저녁(관측: 10-02 15:32 UTC와 17:53 UTC, 09-29 23:45 UTC)에는 전날 봉까지만 주는 일이 있다. 09:34 UTC 실행이 10-02 신호를 커밋한 뒤 시험 장부가 15:32 UTC에 새로 내려받은 데이터는 10-01에서 끝났다. 장부는 "마지막 봉이 장부보다 이전이면 커밋하지 않는" 규칙으로 보호되고, 한국장 신호는 마감 90분 뒤(08:00 UTC)부터 15:00 UTC 사이의 2시간 실행에서 커밋돼야 한다. 그 뒤로 미뤄지면 그날 신호가 빠질 수 있다.
- **체결 가정:** 크립토는 신호 봉 마감과 시가(00:00 UTC)가 같은 시각이고 신호 커밋은 그보다 몇 시간 늦다. 모의 체결가는 커밋 전에 이미 정해진 가격이지만, 신호는 전날 종가까지만 쓰고 매일 처음부터 다시 계산해 커밋된 신호와 대조한다.

## 코스닥 v2 병행 장부 (2026-10-02 시작 승인)

- **무엇:** 현재 코스닥 룰 + 폭(breadth) 레짐 50 — 유니버스 종목 중 200일선 위 비율이 50% 이상인 날만 신규 진입. 근거와 검증은 `docs/swing-upgrade-study-2026-10.md`(실전 조건 CAGR 12.0% → 15.2%, PF 1.23 → 1.40, 최대 낙폭 −44% → −33%).
- **왜 병행인가:** v1 판정(12-23)을 오염시키지 않으면서 개선안을 같은 시장·같은 기간 조건으로 확인하기 위해. v1 장부·판정 기준·기한은 그대로다.
- **운영:** 같은 `swing-paper` 실행에서 시장 `KOSDAQ_V2`로 돌고 장부는 `paper/KOSDAQ_V2/`. 유니버스·세션·벤치마크는 코스닥과 같다. 시작일은 첫 제시간 실행의 기준일(그 전 기록 없음). 판정은 시작일부터 60거래일 뒤, 코스닥과 같은 A~D 기준. 실전 룰을 v2로 바꿀지는 그때 결정한다.
- **시작:** 2026-10-02 (첫 신호 파일 18:51 UTC 커밋, 다음 시가 전). 첫날 레짐 OFF — 유니버스 150종목 중 200일선 위 48.3% (기준 50%), 신규 진입 없음. 150/150 로드. 판정일 2026-12-29 (코스닥 v1 12-23보다 3거래일 뒤).
- **알림:** 이슈 "코스닥 v2 모의투자 신호 알림" 댓글. 보고서에는 "유니버스 중 200일선 위 n% (기준 50%)"가 함께 표시된다.
- **주의:** 백테스트의 폭은 그날의 지수 구성종목, 모의투자의 폭은 현재 상위 150종목으로 계산한다. 가설 13개 중 1개 합격이라 우연일 수 있다는 점은 사전 등록 문서에 적어 두었다.
